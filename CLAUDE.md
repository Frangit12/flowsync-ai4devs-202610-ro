## Overview

FlowSync is a course project (AI4Devs, cohort 202610-ro): a TypeScript monorepo with two independent npm packages — `backend/` (AdonisJS 7 API) and `frontend/` (React 19 + Vite). There is no root `package.json`; run every command from inside the relevant package. Node.js **24+** is required (older versions fail with `Unknown file extension ".ts"`).

The root `README.md` is the exercise brief (generated, do not edit by hand). `prompts.md` is a template where the student logs prompts verbatim.

For the current exercise, **the backend already exists and is not to be modified** — work happens in `frontend/`. Read the backend (especially validators) to learn what the API actually requires.

## Commands

Backend (`backend/`, serves on http://localhost:3333):

```bash
npm install
cp .env.example .env && node ace generate:key   # first time only
node ace migration:run                          # SQLite at backend/tmp/db.sqlite3
npm run dev            # node ace serve --hmr
npm run typecheck      # tsc --noEmit
npm run lint           # eslint (@adonisjs/eslint-config)
npm run format         # prettier (@adonisjs/prettier-config)
npm test               # node ace test (Japa)
node ace test functional                              # one suite (unit | functional)
node ace test --files tests/functional/auth.spec.ts   # one file
node ace test --tests "logs in with valid credentials" # one test by title
```

Test suites are defined in `adonisrc.ts`: `tests/unit/**/*.spec.ts` and `tests/functional/**/*.spec.ts` (functional suite boots the HTTP server). No spec files exist yet. `.env.test` sets `SESSION_DRIVER=memory`.

Frontend (`frontend/`, serves on http://localhost:5173):

```bash
npm install
npm run dev
npm run build          # tsc -b && vite build  (also the type check)
npm run lint           # oxlint
```

The frontend has no formatter or test runner configured. It uses Tailwind v4 + shadcn/ui (`components.json`, components in `src/components/ui/`, add more with `npx shadcn@latest add <name>`), react-router, and the `@/*` → `src/*` alias. Auth lives in `src/lib/` (`api.ts` fetch client, `auth.tsx` token context, `errors.ts` backend-error → Spanish messages) and pages in `src/pages/`.

## Backend architecture

Request flow: `start/routes.ts` → controller (`app/controllers`) → VineJS validator (`app/validators`) → Lucid model (`app/models`) → transformer (`app/transformers`) → `ctx.serialize()`.

- **Routes** are all under `/api/v1`:
  - `POST /auth/signup` → `NewAccountController.store`
  - `POST /auth/login` → `AccessTokensController.store`
  - `GET /account/profile`, `POST /account/logout` — protected by `middleware.auth()`
- Controllers are referenced via the generated `controllers` map from `#generated/controllers` (not direct imports). Imports use the `#alias/*` subpath imports declared in `package.json`.
- **Auth** uses the access-tokens guard (`api`, default in `config/auth.ts`). Tokens are opaque, prefixed `oat_`, sent as `Authorization: Bearer <token>`. A session guard (`web`) is configured but unused by routes.
- **Response envelope**: `providers/api_provider.ts` adds `ctx.serialize()`, which wraps output in `{ "data": ... }`. Signup and login both return `{ data: { user, token } }`; profile returns `{ data: user }`. `UserTransformer` exposes only `id, fullName, email, createdAt, updatedAt, initials`.
- **Validation contract** (`app/validators/user.ts`) — stricter than a product ticket may say:
  - signup: `email` (valid, ≤254, unique in `users`), `password` (8–32 chars), **`passwordConfirmation` (required, must match `password`)**, `fullName` (nullable).
  - login: `email`, `password`.
  - Validation failures return 422 with an `errors` array of `{ message, rule, field }`; bad credentials (`User.verifyCredentials`) return an `E_INVALID_CREDENTIALS` error. Every response is JSON because `force_json_response_middleware` forces `Accept: application/json`.
- **CORS** (`config/cors.ts`) allows any origin in development, none in production unless configured.

### Generated files — do not edit

- `backend/database/schema.ts` is regenerated from the DB by `node ace migration:run`. Models extend these generated schema classes (e.g. `User extends compose(UserSchema, ...)`). Schema changes go in a **new** migration under `database/migrations/`, never by editing tables or `schema.ts`.
- `backend/.adonisjs/**` (controllers map, routes types, Tuyau client registry) is regenerated by the `indexEntities` / `generateRegistry` hooks in `adonisrc.ts` when the dev server/ace runs. The package exports `./registry` and `./data` from there, usable as a typed API client (`@tuyau/core`) from the frontend.
